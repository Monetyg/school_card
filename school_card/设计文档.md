# 荆楚理工移动卡登记 - 设计文档

## 一、需求摘要

| 项目 | 说明 |
|------|------|
| 使用场景 | 管理员通过手机/电脑远程访问，不在同一局域网 |
| 登录认证 | 需要用户名密码登录 |
| 核心功能 | 新增登记、查看全部、编辑、删除、统计看板 |
| 数据字段 | 学号、姓名、学院（固定列表）、电话卡号、原手机号、办理状态 |
| 学号 | 必填、全局唯一，防重复登记 |
| 原手机号 | 必填，11位手机号格式校验 |
| 办理状态 | 未办理 / 办理中 / 已办理 / 已激活（四态） |
| 学院列表 | 11个固定学院，下拉选择 |
| 部署平台 | PythonAnywhere 免费版 |
| 技术栈要求 | Python + Flask + SQLite + 简洁前端 |

---

## 二、技术栈选型

| 层 | 技术 | 选型理由 |
|----|------|----------|
| 后端框架 | **Flask 3.x** | 轻量、灵活、PythonAnywhere 原生 WSGI 支持 |
| ORM | **Flask-SQLAlchemy** | 比原生 sqlite3 更省心，自带防注入，易维护 |
| 用户认证 | **Flask-Login** | 最简单的 session 登录方案，开箱即用 |
| 密码哈希 | **Werkzeug** (Flask内置) | `generate_password_hash` / `check_password_hash` |
| 表单验证 | **Flask-WTF + WTForms** | 后端表单验证，避免手动校验 |
| 数据库 | **SQLite** | PythonAnywhere 免费版支持，零配置，无需额外服务 |
| 前端样式 | **纯 CSS** | 使用 CSS 变量 + 响应式布局，无需任何前端框架 |
| 部署 | **PythonAnywhere Free** | 免费套餐可用，支持 HTTPS 外网访问 |

### 为什么不用其他方案？

| 方案 | 排除理由 |
|------|---------|
| Django | 太重，小型项目杀鸡用牛刀 |
| FastAPI | PythonAnywhere 原生 WSGI 支持不如 Flask 友好 |
| MySQL/PostgreSQL | PythonAnywhere 免费版不支持，需付费 |
| Node.js | 与用户指定的 Python 不符 |
| 前后端分离(Vue/React) | 极简场景不需要，增加构建和部署复杂度 |
| ECharts/Chart.js | 统计量小，纯 CSS 柱状图即可，避免额外依赖 |

### 3.3 路由设计

| 方法 | URL | 功能 | 权限 |
|------|-----|------|------|
| GET/POST | `/auth/login` | 登录页面/处理登录 | 公开 |
| GET | `/auth/logout` | 退出登录 | 需登录 |
| GET | `/` | 学生列表（首页） | 需登录 |
| GET/POST | `/add` | 新增登记 | 需登录 |
| GET/POST | `/edit/<id>` | 编辑学生 | 需登录 |
| POST | `/delete/<id>` | 删除学生 | 需登录 |
| POST | `/status/<id>` | 快捷修改状态 | 需登录 |
| GET | `/stats` | 统计看板 | 需登录 |

### 3.4 请求处理流程

```
用户请求 → Flask WSGI → 路由匹配 → @login_required 检查
    │
    ├── 未登录 → 重定向到 /auth/login → 登录成功 → 跳回原页面
    │
    └── 已登录 → 视图函数处理 → 数据库操作 → 渲染模板 → 返回 HTML
```

### 4.2 表结构详解

#### users 表（管理员账号）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 用户ID |
| username | TEXT | NOT NULL, UNIQUE, INDEX | 登录用户名 |
| password_hash | TEXT | NOT NULL | Werkzeug 生成的密码哈希 |
| created_at | DATETIME | NOT NULL, DEFAULT now | 账号创建时间 |

#### students 表（学生登记信息）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 记录ID |
| student_id | TEXT | NOT NULL, UNIQUE, INDEX | 学生学号（全局唯一防重复） |
| name | TEXT | NOT NULL, INDEX | 学生姓名 |
| college | TEXT | NOT NULL | 学院名称（来自固定列表） |
| phone_card_number | TEXT | NOT NULL, UNIQUE, INDEX | 电话卡号（全局唯一防重复） |
| original_phone | TEXT | NOT NULL | 原手机号（11位，表单层格式校验） |
| status | TEXT | NOT NULL, DEFAULT '未办理' | 四态之一：未办理/办理中/已办理/已激活 |
| created_at | DATETIME | NOT NULL, DEFAULT now | 登记时间 |
| updated_at | DATETIME | NOT NULL, DEFAULT now, ON UPDATE now | 最后修改时间 |

### 4.3 字段设计说明

**学号 UNIQUE 唯一约束**
- 防止同一名学生被重复登记
- 同时加 INDEX 加速搜索
- 与电话卡号类似，应用层在捕获唯一约束冲突后区分提示「学号已被登记」或「卡号已被登记」

**原手机号格式校验**
- 表单层通过正则 `^1\d{10}$` 强制 11 位大陆手机号格式
- 必填字段，登记与编辑时均需填写

**电话卡号 UNIQUE 唯一约束**
- 防止同一张卡被重复登记，避免数据混乱
- 同时加 INDEX 加速搜索

**status 为什么用 TEXT 而非 INTEGER**
- 四态值固定且语义清晰，TEXT 可读性好
- 无需额外映射表，减少复杂度
- 应用层通过 `Config.STATUS_CHOICES` 校验合法性

**college 为什么不建独立学院表**
- 11个学院是固定的，变更频率极低
- 省去建表、预填充、关联查询的复杂度
- 维护方式：修改 `config.py` 中的 `COLLEGES` 列表
- 将来如需学院管理功能，可轻松迁移为独立表

### 4.4 SQLite 建表 DDL（参考，实际由 SQLAlchemy 自动生成）

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at DATETIME NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX ix_users_username ON users (username);

CREATE TABLE students (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    college TEXT NOT NULL,
    phone_card_number TEXT NOT NULL UNIQUE,
    original_phone TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT '未办理',
    created_at DATETIME NOT NULL DEFAULT (datetime('now')),
    updated_at DATETIME NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX ix_students_name ON students (name);
CREATE UNIQUE INDEX ix_students_student_id ON students (student_id);
CREATE UNIQUE INDEX ix_students_phone_card_number ON students (phone_card_number);
```

## 五、安全设计

| 安全措施 | 实现方式 |
|---------|---------|
| 密码存储 | Werkzeug `generate_password_hash`（PBKDF2 + SHA256 加盐哈希） |
| 登录保护 | Flask-Login session 管理，除登录页外所有页面需登录访问 |
| 表单 CSRF | Flask-WTF 自动生成 CSRF token |
| 输入验证 | WTForms 后端校验（长度、格式、必填） |
| SQL 注入 | SQLAlchemy ORM 参数化查询，不存在拼接 SQL |
| 学号唯一 | 数据库 UNIQUE 约束 + 应用层区分提示「学号已被登记」 |
| 电话卡号唯一 | 数据库 UNIQUE 约束 + 应用层区分提示「卡号已被登记」 |
| 原手机号格式 | 正则 `^1\d{10}$` 校验 11 位大陆手机号 |
| 电话卡号格式 | 正则校验：仅允许字母、数字、短横线 |

## 九、部署方案

### PythonAnywhere 免费版部署流程

1. 注册账号（https://www.pythonanywhere.com）
2. 上传项目文件到 `/home/用户名/school_card/`
3. 创建虚拟环境并安装依赖
4. 修改 `config.py` 中数据库路径为 home 目录下的绝对路径
5. 运行 `init_db.py` 创建管理员账号
6. 配置 WSGI 文件指向 `create_app()`
7. 配置静态文件路径
8. 重载 Web 应用

详细步骤见 [DEPLOY.md](DEPLOY.md)。
